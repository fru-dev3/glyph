01 — WHY IT MATTERS NOW

One agent needed no name. Nine do.

A year ago you ran a single assistant in a single terminal. Now agents run in parallel, on machines you are not sitting at, and you check them from a phone. Identity stopped being cosmetic.

×9

Parallel by default

Worktrees, fleets and background runs mean several agents are alive at once. Anonymous panes make it guesswork which one is which.

3

Across machines

A laptop, a desktop, a cloud box. The same repo open in three places, and nothing in the session list says where the work is happening.

Answered from a phone

Remote Control puts a permission prompt on your lock screen. You have to know which session is asking before you can safely say yes.

03 — THE MARK

Four facts, one line

Composed before the process starts, so a session is never briefly nameless.

billing·Acme API·laptop·2026-09-12·0556
LabelWhat you called it, or the project if you said nothing.
ProjectThe git repo, title-cased. Overridable.
MachineFrom the hostname: laptop, studio, desktop, hetzner.
StartedDate and time, so idle work is obvious.

04 — USAGE

Keep typing what you already type

One bare word is your label. Anything with a space is a prompt.

  • Claude Code takes the mark as a real session name and carries it to your phone.
  • Everyone else gets it on the terminal title, the tmux window and glyph ls.
  • -p, --print and subcommands pass through untouched.

$ claude billing
launches  claude -n 'billing·Acme API·laptop·0648'

Why a shell wrapper and not a plugin

A session name must exist before the process starts, so it can only come from argv. Plugins and SessionStart hooks run after that.

  • Claude Code's --remote-control <name> opens the bridge but does not name the session — only -n does.
  • In zsh, argv is $@; declaring local -a argv silently empties the positional parameters.
